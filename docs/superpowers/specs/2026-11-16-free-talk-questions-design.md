# 自由に話してから問いのリストで深掘りする 設計

日付: 2026-11-16
状態: 確認待ち
前の設計: [2026-11-13-why-why-talk-design.md](2026-11-13-why-why-talk-design.md)(論点を一つ決めて一本の木を掘る版)

## 目的となぜ

今は `--topic` で論点を一つ決めてから始まり、Gemini がその一本の木を 5 段まで掘ります。ユーザーの言葉では「テーマをがっつり決めてるとあまり意味がない」。論点を先に決めると、本当に話したいことからずれてしまいます。

これからは次の流れにします。

1. **自由に話す**: 人がまず思うままに話し、文字起こしだけを取る。Gemini は黙って聞く(返事も相づちもしない)。
2. **ファイルを読む**: 添付ファイル(テキスト・Markdown・PDF・画像)も読み込む。
3. **問いに分ける**: 話とファイルを、Gemini(文章用のモデル)が最大 10 件の問いのリストに分ける。
4. **チェックする**: 人が画面で問いを選ぶ(最初は全部未チェック)。文を直す・足す・消す・並べ替えるもできる。
5. **深掘りする**: チェックした問いを、リストの順に一つずつ、今まで通り声でなぜなぜ 5 段まで掘る。5 段に届いたら Gemini が自分で次の問いへ進む。
6. **送る**: 問いごとの方針・理由・見送った案・残った疑問と、木と会話の全文をエージェントに返す。

`--topic` は任意です。渡されたときは自由に話す段階を飛ばし、論点と `--context`・添付ファイルからすぐに問いのリストを作ります(ユーザー決定)。

## 目標・目標外・失敗とみなすもの

**目標**
- 論点なしで `why-why-talk` を呼べて、自由に話す → 問いのリスト → 深掘り → 送信が一つの画面の中で終わる。
- 自由に話した内容が、言葉の抜けなく文字起こしされる。
- チェックした問いがすべて、リストの順に一つずつ 5 段を目安に掘られる。
- 結果は問いごとに方針・理由・見送った案・残った疑問を持つ。手をつけなかった問いは「未着手」と分かる。

**目標外**
- Word・Excel・音声・動画の添付(ユーザー決定: テキスト・Markdown・PDF・画像のみ)。
- 深掘りの途中でリストに戻って問いを足すこと。
- 問いをまたいだ全体のまとめ(受け取ったエージェントが計画の中で作る。ユーザー決定)。
- 自由に話す段階で Gemini が質問・相づちをすること(ユーザー決定: 黙って聞く)。

**失敗とみなすもの**
- 自由に話している間に Gemini の声が流れる、または Gemini が話題を誘導する。
- 文字起こしで言葉が抜け、問いのリストが話した内容とずれる。
- チェックしていない問いが掘られる、またはチェックした問いが黙って飛ばされる。
- 添付ファイルの中身や API キーが、伏せられずに出力やファイルに残る(今と同じ秘密の伏せ方を通す)。API キーがブラウザに渡る。
- 今の「論点を渡して深掘りする」呼び方が壊れる(`--topic` と `--context` はそのまま使える)。

## 作り方の案

### 自由に話す段階の文字起こし(ユーザーが B を選択)

2026-11-16 に本物の Gemini で試した(合成した日本語音声 15 秒):

- **A. Gemini Live で聞き、返事は画面で捨てる**: 文字は話しながら出る。ただ「返事をしない」と指示しても毎回数秒の音声を返し、2 回目は区切りで「気が」が抜けた。自動の区切りを切ると文字起こしが一切返らなかった。
- **B. 録音し、話の切れ目ごとに Gemini Flash で文字起こし**: 15 秒の音声が 5.5 秒で、句読点つき・抜けなしで返った。文字は切れ目のあと数秒で出る。

B を選んだ理由: 問いのリストの元になる文字起こしは正確さが一番大事で、数秒の遅れは困らない。Gemini が返事をする余地がない。添付ファイルを読むのと同じモデルで済む。

### 問いに分ける場所(ユーザー決定)

コマンドの中で Gemini(文章用のモデル)が分ける。同じ画面のまま数秒でリストが出る。エージェントが分ける案は、一度画面が切れて二段構えになるので見送った。

### 深掘りの進め方(ユーザー決定)

リストの順に一つずつ。5 段に届いたら Gemini が自分で次へ進む(人の確認は待たない)。Gemini が話の流れで問いを行き来する案は、どこまで掘れたか追いにくいので見送った。

## 決まった作り方

### 段階

セッションに段階(`phase`)を持たせる: `free_talk`(自由に話す)→ `questions`(リストをチェック)→ `deep_dive`(深掘り)。送信と取りやめは今まで通りどの段階からでもできる。`--topic` があれば `questions` から始まる。

### 自由に話す段階

- 画面は今のマイク選びと音量表示を使い、録音する。Gemini Live にはつながない。
- 録音は話の切れ目(1〜2 秒の無音、長くても 30 秒)ごとに区切ってコマンドへ送る。コマンドが Gemini Flash(`gemini-3.8-flash`)で日本語に文字起こしし、文字起こしに足して画面に返す。
- 区切りの文字起こしが失敗したら、その区切りの音声を残し、画面に「文字起こしに失敗した部分があります(再試行)」を出す。黙って捨てない。
- 「問いに分ける」ボタンでこの段階を終える。

### 添付ファイル

- 渡し方は二つ(ユーザー決定): 画面にドラッグする、エージェントが `--attach <file>` で渡す(何度でも指定可)。
- 受け付ける種類: テキスト・Markdown・PDF・画像。それ以外は理由を出して断る。1 ファイルの大きさに上限を置く(Gemini にそのまま渡せる大きさ)。
- コマンドが Gemini Flash でファイルの要点を日本語の文章にする。要点は画面に出し、問いを作るときと深掘りのときに Gemini に渡す。要点にも今の秘密の伏せ方を通す。
- ドラッグは自由に話す段階とリストの段階でできる。

### 問いのリスト

- 「問いに分ける」で、文字起こし・ファイルの要点・`--topic`・`--context` を Gemini Flash に渡し、最大 10 件の問いを決まった形(JSON)で受け取る。各問いは一文で、話した人の言葉を使う。
- 画面は問いごとにチェック欄。最初は全部未チェック。文を直す・足す・消す・並べ替えるができる。「もう一度分ける」で作り直せる。
- `--topic` から始まったときも「もう少し話して問いを足す」で自由に話す段階へ戻れる(設計者の判断)。
- 一つ以上チェックすると「深掘りを始める」が押せる。

### 深掘り

- 「深掘りを始める」で Gemini Live とつなぐ。チェックした問いが、それぞれ一本の木の根になる(根の id は `q1`, `q2`, …、リストの順)。今の木の決まり(親のないノードを作らない、枝を消さない、5 段より浅い葉には理由が要る)はそのまま。
- Gemini への指示に、問いのリスト、今掘っている問い、自由に話した内容、ファイルの要点、`--context` を入れる。
- 今の問いの 5 段に届かない枝がなくなったら(少なくとも一本が 5 段に届き、掘りかけの浅い枝が残っていない)、Gemini はその問いの方針を下書きし(`propose_direction` に問いの id を足す)、声で一言伝えて、確認を待たずに次の問いへ進む(新しい関数 `next_question`)。最後の問いが終わったら「全部終わりました。送信してください」と伝える。
- 画面には問いの一覧と、今掘っている問い・終わった問い・未着手の問いを出す。人が「次の問いへ」を押して飛ばすこともできる(飛ばした問いは「途中」として結果に残る。設計者の判断)。
- 役割の交代(Gemini に聞く)、つなぎ直し、止まったときの呼びかけ直しは今のまま。

### 結果

- 結果の Markdown は問いごとの節を持つ: 問い・状態(終わった / 途中 / 未着手)・方針・理由・見送った案・残った疑問・深さ不足の枝・その問いの木。
- 共通の節: 添付ファイルと要点、Gemini に聞いたこと、自由に話した文字起こし、深掘りの会話の全文。
- 見出しは今の `# 深掘りの結果:` を残す(エージェントが成功を見分ける目印)。論点がないときは問いの数を入れる。
- 送信前に人が問いごとの方針を直せる(今の下書き欄を問いごとにする)。

### コマンドとスキル

- `--topic` は任意、`--attach <file>` を足す。`--context` はそのまま。
- `why-why-talk` スキル(この repo の `skills/why-why-talk/` と implementation の `.agents/skills/why-why-talk/`、同じ内容に保つ)を新しい流れに書き直す。いつ論点を渡すか、結果の読み方(問いごと)を書く。
- README とドメインモデルを新しい流れに合わせる。

### 設計者の判断(作る人の確認で出た点)

- **木は一つのまま根を複数にする**: 今の木(`Analysis`)に、問いごとの根(`parentId` が空のノード `q1`…)を足す。段数の数え方はもともと根ごとに数えるので変わらない。根を足す関数を `analysis.ts` に足し、`n0` は論点なしのとき作らない。「親のないノードを作らない」の決まりは「根以外」に読み替える。
- **結果の JSON は作り直してよい**: 読んでいるのはこの道具のスキルだけで、公開から 3 日。`questions[]`(問いごとの状態・方針・木)の形に変える。互換の層は作らない。
- **次の問いへ進めるかはコマンドが確かめる**: `next_question` は、今の問いに 5 段に届いた枝が一本以上あり、掘りかけの浅い枝が残っていないときだけ通す。足りなければ理由と残りの枝を返して断る(Gemini が黙って飛ばすのを防ぐ)。人の「次の問いへ」ボタンだけはこの確かめなしで進み、その問いは「途中」になる。
- **録音はブラウザの中だけに置く**: 区切りの音声は文字起こしが終わるまで画面のメモリに持ち、ファイルには書かない。残すのは文字起こしだけ。
- **文章用のモデルは一つ**: 文字起こし・ファイルの要点・問いに分けるのは、どれも `gemini-3.8-flash`。環境変数 `WHY_WHY_TEXT_MODEL` で変えられる。
- **深掘りせずに送ったとき**: どの段階でも送信は今まで通り終了コード 0。結果には自由に話した文字起こし、ファイルの要点、問いのリスト(すべて「未着手」)が入る。
- **長い会話**: 問い 10 件でも続くよう、つなぎ直すときの指示に「今の問い」と終わった問いを入れて、その問いから続ける。診断の記録の上限(5000 件)は今のまま。

## 作る人に任せること

- 話の切れ目の見つけ方(画面の音量で無音を見るなど)と、区切りを送る形式(WAV など)。
- 1 ファイルの大きさの上限の値と、PDF のページ数の扱い。
- 問いを作る指示文の細部と、Flash の構造化出力の形。
- 画面の細かな見た目。今の画面の作りに合わせる。
