# why-why talk 設計(声で壁打ちして方針を送る)

日付: 2026-11-13
状態: 確認待ち
前の設計: [2026-11-13-why-why-mcp-design.md](2026-11-13-why-why-mcp-design.md)(MCP 版。ユーザーの判断で置き換え)

## 目的

計画のスキル(`/planning-nowly` など)の途中で、**ある一点を深掘りしたいとき**に呼び出す道具です。

- エージェントが、論点と調べた内容を渡してコマンドを実行すると、手元の画面がブラウザで開きます。
- 人は、Gemini Live API と**声で壁打ち**します。Gemini は聞き手で、「なぜ?」「他には?」と掘り下げます。
- 会話の途中で、Gemini がこちらの関数を呼んで**なぜの木**を育てます。木は画面にその場で表示されます。
- 最後に Gemini が方針の下書きを作り、人が直して**送信**します。コマンドは結果を出力して終わり、エージェントは計画の続きにそれを使います。

返し方は、Plannotator の計画レビュー(`plannotator annotate`)と同じ形です。コマンドが画面を開き、人が決めるまで待ち、結果を標準出力に書いて終わります。

## 目標・目標外・失敗とみなすもの

**目標**
- スキルから1つのコマンドで呼べて、送信された結果がそのままエージェントに届く(Claude Code と Codex)。
- 日本語の声で、20〜30分の壁打ちが途切れずにできる。
- 送る中身: **方針・理由・見送った案・残った疑問・なぜの木・会話の全文**(ユーザー決定)。
- 送信の前に、人が方針の欄を直せる(設計者の判断。ユーザーが不要と言えば外す)。

**目標外**
- 常に動いている画面や、送り先のターミナルを選ぶ仕組み(Inbox 型)。始まりは常にエージェント。
- Claude Code 用のプラグイン。
- Clef での評価(会話の中で Gemini が判断する)。
- MCP サーバー(呼び出しの時間切れで長い壁打ちが切れるため)。

**失敗とみなすもの**
- Gemini の API キーがブラウザに渡る。
- 人が送信していないのに、結果が送られたことになる。逆に、タブを閉じたのにエージェントが永遠に待つ。
- 15分などの区切りで会話が切れ、そこまでの木や会話が消える。
- 木の形が崩れる(親のないノード、枝が消える)。
- 秘密情報(トークンなど)が、出力やファイルにそのまま残る。

## 作り方の案(ユーザーが A を選択)

| 案 | 内容 | 評価 |
|---|---|---|
| **A. コマンド + 手元の画面。木は会話中に Gemini が育てる**(採用) | Gemini が関数を呼んで木を足す。画面に木がその場で育つ | 話しながら掘り残しに気づける。前の版の木の部品を使える |
| B. コマンド + 手元の画面。木は会話の後に作る | 会話の全文から、別のモデルが木と方針をまとめる | 会話は簡単だが、話している間は木が見えない |
| C. MCP の道具として呼ぶ | MCP の呼び出しの中で、送信まで待つ | 呼び出しの時間切れで、長い壁打ちが切れるおそれ |

## 前提と制約(公式ドキュメントで確認、2026-11-13)

- モデル: `gemini-3.8-live`(GA、音声から音声の会話向けの既定)。入力 131,072 トークン。会話中の関数呼び出しは、同期・非同期の両方に対応。
- 日本語: 対応(`ja`)。言語は自動で判定され、指定はできない。言語はシステム指示で縛る。
- 音声: 入力は 16 kHz の PCM16、出力は 24 kHz の PCM16。
- 文字起こし: `inputAudioTranscription` と `outputAudioTranscription` で、人と Gemini の両方の文字起こしが取れる。
- 会話の長さ: 圧縮なしの音声だけの会話は15分で終わる。1つの接続は約10分。`contextWindowCompression: { slidingWindow: {} }` と `sessionResumption`(引き継ぎの番号は2時間有効)で延ばす。切れる前に `goAway` が届く。
- ブラウザからの接続: `@google/genai`(3.3.0)の `ai.live.connect`。本物のキーは使わず、手元のサーバーが `authTokens.create` で作る短期のトークン(`v1beta`、既定で開始1分・有効30分)を渡す。
- 料金: 音声入力 1分あたり約0.005ドル、出力 約0.018ドル。30分で1ドル未満。
- API キー: 環境変数 `GEMINI_API_KEY`(この Mac では設定済み。他の製品と同じ AI Studio のキー)。

## 設計

### 呼び出し方

```
npx -y github:nowly-lab/why-why-talk --topic "<論点>" [--context <file>] [--out <dir>] [--no-open]
```

- `--topic`: 深掘りする論点(1行)。
- `--context`: エージェントが調べた内容(Markdown など)。Gemini への指示に入れる(最大 60,000 文字。超えた分は切って、切ったことを書く)。
- `--out`: 結果を書くフォルダ。既定は `<cwd>/.why-why/<日時>-<論点の短い名前>/`。
- 画面の URL は標準エラーに必ず出す。`--no-open` ならブラウザは開かない。
- 終わり方(終了コード):
  - **0 送信**: 標準出力に結果の Markdown を書く。
  - **1 取りやめ**: 人が「取りやめ」を押した、またはタブを閉じて60秒戻らなかった。標準出力に `取りやめ` と、それまでの記録の場所を書く。
  - **2 失敗**: 起動できない(キーがない、ポートが取れない、など)。
- エージェント側の待ち方(スキルに書く):
  - Claude Code: Bash の `run_in_background`(最大2時間)で実行し、終わったら通知で結果を受け取る。
  - Codex: 前面で、長い時間切れ(最大)を付けて実行する。

### 構成

```
エージェント ──コマンド──▶ 手元のサーバー(127.0.0.1、空いているポート)
                              │ 画面を配る / 短期トークンを作る / 木と会話を持つ / 結果を出す
                              ▼
                         ブラウザの画面 ◀──声──▶ Gemini Live(トークンで直接つなぐ)
                              │ Gemini の関数呼び出しを、サーバーに渡して木を変える
```

- **サーバー**(Node、`node:http`): 画面と JS を配り、次の API を持つ。どの書き込みも、起動時に作った番号(セッションの合言葉)が合わなければ断る(古いタブ対策)。
  - `GET /api/session`: 論点・合言葉・今の木・会話・方針の下書き(画面を開き直しても続きから)。
  - `POST /api/token`: 短期トークンを作る(`uses: 1`、開始1分・有効30分。モデル・システム指示・関数をトークンに固定する `liveConnectConstraints`)。つなぎ直しのたびに呼べる。
  - `POST /api/tool`: Gemini の関数呼び出しを木に反映し、結果を返す。
  - `POST /api/transcript`: 文字起こしを足す(話した人・時刻・文)。
  - `POST /api/submit`: 送信(方針の欄の内容つき)。`POST /api/cancel`: 取りやめ。
  - `GET /api/lease`(SSE): タブが開いているかの見張り。切れて60秒戻らなければ取りやめ。
- **画面**(ブラウザ、esbuild でまとめた JS): マイク、Gemini との接続、音声の再生、文字起こしの表示、木の表示、方針の欄、送信と取りやめのボタン。
- **木**: 前の版の部品(`src/model.ts`、`src/analysis.ts`、`src/redact.ts`、`src/render/mermaid.ts`)をサーバー側で使う。根は論点。
- **保存**: 木・会話・方針は、変わるたびに `--out` のフォルダへ書く。途中で落ちても、そこまでは残る。

### Gemini への指示(システム指示)

- 役割: 聞き手。一度に1つだけ、短く質問する。答えを急がせない。
- 掘り方: 「なぜ?」で深く、「他には?」で横に広げる。観点(仕組み・道具/人・体制/手順・プロセス/検知/前提・外部)を、掘り残しを探すチェックリストとして使う。
- 確かめ方: 「それだけで起きますか?」で横の見落としを、逆から「だから」でつないで縦の飛躍を確かめる。
- 木: 新しい理由が出たら `add_whys`、事実が出たら `add_fact`、枝を止めるときは `update_branch`。木の ID を声で読み上げない。
- 言語: 日本語で話す(公式の推奨どおり、指示の中で強く縛る)。
- 材料: 論点と、エージェントから渡された内容。
- 終わり方: 人が「まとめて」と言うか、画面の「整理する」を押したら、`propose_direction` を呼んで方針の下書きを作り、要点を声で短く伝える。

### Gemini に渡す関数

| 関数 | 中身 |
|---|---|
| `add_whys` | 親の ID と、なぜの候補(文と観点)。同じ親に同じ文は足さない |
| `add_fact` | 枝の ID と、人が話した事実(支持するか否定するか) |
| `update_branch` | 枝を「掘っている・葉(対策つき)・仮説(理由つき)・却下(理由つき)・未調査に戻す」 |
| `propose_direction` | 方針・理由・見送った案・残った疑問の下書き |

- 関数の結果には、変わった後の木の要約(ID と文と状態)を返し、Gemini が ID を取り違えないようにする。
- 失敗(ID が違う、状態の移り方が違う)は、理由を結果として返し、Gemini が言い直せるようにする。
- `gemini-3.8-live` は同期の関数呼び出しにも対応しているので、まずは同期で呼ぶ(木の更新は一瞬で終わる)。

### 会話を途切れさせない

- `contextWindowCompression: { slidingWindow: {} }` と `sessionResumption` を常に使う。
- `goAway` が来たら、または接続が切れたら、新しいトークンを取り、引き継ぎの番号でつなぎ直す。画面には「つなぎ直しています」と出す。
- 引き継ぎの番号が使えないとき(2時間を過ぎたなど)は、木の要約と会話の最後の部分を渡して、新しい会話として続ける。

### 送る結果(標準出力と `result.md`)

```markdown
# 深掘りの結果: <論点>
## 方針
## 理由
## 見送った案
## 残った疑問
## なぜの木
(Mermaid と、ID・状態・観点・事実・対策の一覧)
## 会話の全文
(時刻・話した人・文)
---
files: <out>/result.md, result.json, tree.mmd, transcript.md
```

- `result.json` には同じ内容を構造化して入れる(エージェントが部分だけ読めるように)。
- 秘密情報は、前の版の `redactSecrets` で、保存と出力の前に伏せる。

### スキル

- このリポジトリに `skills/why-why-talk/SKILL.md`: いつ使うか、コマンドの呼び方(Claude Code は裏で実行、Codex は前面)、`--context` に何を書くか、結果の使い方(方針を計画に取り込み、残った疑問は Inbox で人に確かめる)。

### 前の版から変えるもの

- 残す: `src/model.ts`、`src/analysis.ts`、`src/redact.ts`、`src/render/mermaid.ts` とそのテスト。
- 外す: MCP サーバー(`src/server.ts`、`src/index.ts` の MCP 起動)、Clef(`src/clef.ts`)、評価と `nextBranch`、HTML の描画(画面に置き換え)、MCP 用のスキル。
- ドメインモデルは、新しい流れ(呼び出す → 話す → 木が育つ → 整理する → 送信)に作り直す。

## 細かい決まり(設計者の判断)

ビルダー確認で出た点を、次のように決めました。

1. **トークンは接続ごとに作る**: `POST /api/token` は呼ばれるたびに、**その時点の状態から**システム指示を組み立てて、トークンに固定する。引き継ぎの番号が使えないときの新しい会話では、システム指示に木の要約と会話の最後の部分(最大 8,000 文字)を入れる。
2. **トークンの期限**: 1つの接続は約10分で `goAway` が来るので、接続ごとに新しいトークン(有効30分)を取ってつなぎ直す。期限の切れたトークンで会話を続けることはない。`goAway` が来なくても、接続から25分たったら自分からつなぎ直す。
3. **Clef 用の部分は外す**: 評価(`evaluation`、有力度・影響など)と `nextBranch` は消す。どの枝を掘るかは、会話の中で Gemini と人が決める。事実は `{ summary, supports }` だけにする(種類の区別はなくす)。残すのは、木の形・状態の移り方・伏せ字・Mermaid の描画とそのテスト。
4. **画面の JS の配り方**: `prepare` で `tsc` と esbuild を実行して `dist/` に作る(コミットしない)。`npx github:` で入れると、そのときに作られる(前の版で動くことを確認済み)。最初の起動だけ少し時間がかかる。
5. **伏せ字の範囲**: 画面に出す文字起こしは、その場の自分の会話なので伏せない。保存と出力の前に伏せる。Gemini に渡す `--context` も伏せてから渡す。
6. **送信の条件**: 「整理する」を押していなくても送信できる。ただし、方針の欄が空なら送信できない。掘っている途中の枝があっても送れる(その状態のまま結果に書く)。

## 名前・配り方・確認(ユーザー決定、2026-11-13)

- リポジトリ名は `nowly-lab/why-why-talk`(`why-why-mcp` から変更済み)。コマンドは `why-why-talk`。
- 公開は main へのマージまで。npm には公開しない(前の版の決定を引き継ぐ)。
- 手順のスキル `why-why-talk` を、このリポジトリと implementation リポジトリの `.agents/skills/` の両方に置く。MCP の登録はしない。
- マージの前に、ユーザーが実際の論点で一度、声で試して送信する。
- 今の Gemini キーで進めてよい(無料枠なら会話が Google の改善に使われることも了承済み)。

## ビルダーに任せること

- 画面の見た目、音声の取り回し(AudioWorklet など)、ファイル構成。
- 声の種類(日本語で聞きやすいものを試して既定を決める。環境変数で変えられるようにする)。
- 文字起こしのまとめ方(細切れの文字起こしを、発言ごとにまとめる)。
